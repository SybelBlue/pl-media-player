# PL Media Player

`pl-media-player` is a reusable PrairieLearn course element for audio and video prompts. It can
limit playback sessions, control pausing, seeking, and muting, remember playback and volume state
in the browser, and select media from a question directory when a variant is prepared.

This repository is both the source of the element and a PrairieLearn demonstration course. The
`release` branch is generated by `pl-vendor` and contains a compact, directly vendorable element
distribution.

## Features

- Accessible audio and video controls with native HTML media playback.
- Unlimited playback or a positive `max-plays` session budget.
- A three-tone volume check before limited playback.
- Pause/resume within one session without double-counting.
- Optional pause and seeking restrictions.
- Origin-wide volume memory with same-page player synchronization.
- Limit-aware muting control that prevents silent playback by default for limited players.
- Optional remaining-attempt display and clear exhaustion feedback.
- Reload-safe playback counts backed by browser storage and submitted inputs.
- Explicit question-local or course-local files.
- External media from HTTP(S) URLs, including embedded YouTube videos.
- Manifest-free random selection from a directory during `prepare()`.
- Independent state for multiple players in one question.

These controls deter casual replay; they are not DRM or server-authoritative enforcement. A
technically capable student can inspect or request a client-accessible media URL and can alter
browser storage or JavaScript state.

## Install with `pl-vendor`

Install `pl_vendor` as a uv development dependency in the consuming course, then vendor the
generated `release` branch directly into the course element directory:

```sh
uv add --dev pl_vendor
uv run pl-vendor add \
  pl-media-player \
  https://github.com/ORG/pl-media-player.git \
  elements/pl-media-player \
  --branch release
uv run pl-vendor check installed
```

Replace the example URL after this repository has a public GitHub remote. Commit the consumer's
`pyproject.toml`, `plvendor-lock.yaml`, and generated `elements/pl-media-player` tree together.
Use `uv run pl-vendor update pl-media-player` to advance to a newer release-branch commit.

For a manual installation, copy `elements/pl-media-player` into the `elements` directory of a
PrairieLearn course.

## Usage

Every `pl-media-player` requires a `player-id` that is unique within the question. The ID namespaces
the element's submitted playback count and any browser-local persistence.

Basic audio:

```html
<pl-media-player file-name="conversation.wav" player-id="conversation"></pl-media-player>
```

Two allowed sessions, with pause/resume but no seeking:

```html
<pl-media-player
  allow-pause="true"
  allow-seeking="false"
  file-name="conversation.mp3"
  max-plays="2"
  player-id="conversation"
></pl-media-player>
```

Players with `max-plays` prevent muting and zero volume by default. They also show a test-sound
button that plays three tones at increasing volume without using a playback attempt. Override the
muting behavior when needed:

```html
<pl-media-player
  allow-muting="true"
  file-name="conversation.mp3"
  max-plays="2"
  player-id="conversation"
></pl-media-player>
```

Playback limits are automatically persisted across reloads of the current question page:

```html
<pl-media-player
  file-name="conversation.mp3"
  max-plays="2"
  player-id="listening-prompt"
></pl-media-player>
```

Random direct child of a question-local directory:

```html
<pl-media-player
  directory="clientFilesQuestion"
  extensions="mp3, wav"
  max-plays="2"
  player-id="random-prompt"
  randomize="true"
  source-directory="listening/unit-01"
></pl-media-player>
```

Course-local media is also supported:

```html
<pl-media-player
  directory="clientFilesCourse"
  file-name="shared/listening-prompt.mp3"
  player-id="shared-prompt"
></pl-media-player>
```

External media can be loaded from an absolute HTTP(S) URL:

```html
<pl-media-player
  player-id="external-prompt"
  url="https://cdn.example.com/listening-prompt.mp3"
></pl-media-player>
```

For extensionless URLs and streaming endpoints, specify the media family explicitly:

```html
<pl-media-player
  media-type="video"
  player-id="stream"
  url="https://media.example.com/playback?id=example"
></pl-media-player>
```

YouTube watch, share, Shorts, live, and embed URLs are converted to an HTTPS embed:

```html
<pl-media-player
  player-id="video"
  url="https://www.youtube.com/watch?v=dQw4w9WgXcQ"
></pl-media-player>
```

A YouTube URL cannot be combined with attributes other than the required `player-id`. Playback
budgets, persistence, and the native pause, seek, and mute restrictions do not apply inside the
YouTube iframe.

Publicly shared PrairieLearn questions should use `clientFilesQuestion`: shared questions cannot
depend on the source course's `clientFilesCourse`.

## Attributes

| Attribute                    | Default               | Description                                                                           |
| ---------------------------- | --------------------- | ------------------------------------------------------------------------------------- |
| `file-name`                  | —                     | Explicit POSIX-relative path below the selected client-files root.                    |
| `url`                        | —                     | Absolute HTTP(S) media or YouTube URL; mutually exclusive with other source options.  |
| `directory`                  | `clientFilesQuestion` | `clientFilesQuestion` or `clientFilesCourse`.                                         |
| `source-directory`           | —                     | Direct-child discovery directory used with `randomize="true"`.                        |
| `randomize`                  | `false`               | Select and persist one eligible file during variant preparation.                      |
| `max-plays`                  | unlimited             | Positive number of playback sessions allowed.                                         |
| `allow-muting`               | `auto`                | `auto`, `true`, or `false`; auto prevents silence when playback is limited.           |
| `allow-overlapping-playback` | `false`               | Permit simultaneous playback when every active player also opts in.                   |
| `allow-pause`                | `true`                | Permit pausing and resuming the active session.                                       |
| `allow-seeking`              | `true`                | Permit moving within the active session.                                              |
| `show-remaining`             | `true`                | Show the remaining session count or the unlimited label.                              |
| `media-type`                 | `auto`                | `auto`, `audio`, or `video`; required for URLs without a recognized extension.        |
| `extensions`                 | supported formats     | Comma-separated discovery filter; only valid with random selection.                   |
| `player-id`                  | required              | Unique namespace for submitted playback state and browser-local persistence.          |

Supported extension families are WAV, MP3, Ogg audio, AAC/M4A, FLAC, MP4/M4V, WebM, Ogg video,
and QuickTime MOV. Actual codec playback depends on the student's browser and operating system;
MP3/WAV for audio and H.264 MP4/M4V for video have the broadest practical support.

## Playback semantics

An attempt is one playback session, not one native `play` event. The attempt is consumed when the
browser reports that media is actually playing, so a load failure before playback does not consume
the budget. An allowed pause and resume stays in the same session. Replaying after `ended` begins a
new session. Once the budget is exhausted, a new session is paused and a visible message is shown.

While a limited playback session is active, PrairieLearn treats the question form as dirty so that
leaving the page triggers its unsaved-changes warning. The form becomes clean again when playback
reaches the end, unless another answer has changed.

By default, starting a native audio or video player pauses other active `pl-media-player` instances
on the page. If a conflicting player has `allow-pause="false"`, the new playback is blocked without
using an attempt. Simultaneous playback is allowed only when every involved player sets
`allow-overlapping-playback="true"`. YouTube embeds are outside this coordination.

The consumed count is written to both a submitted hidden input and browser storage. On
initialization, the greater of those counts wins. The input carries progress through Save and Save
and Grade, while browser storage covers reload, back/forward navigation, tab close, and other
unloads that do not submit the form. Storage keys contain a browser history-entry identity and the
stable player identity. The history identity survives reload even when PrairieLearn's instructor
preview creates a new server variant, while an explicit New variant navigation starts with a fresh
identity and budget. If local storage is unavailable, the input still carries progress through
submissions and playback continues with in-memory limits without an uncaught error.

Volume is saved as a learner preference shared by all `pl-media-player` instances on the same
origin. A change updates other players already initialized on the page and is restored on later page
loads. Numeric volume is remembered, including zero, but the native muted state is not. When a
player disallows muting, it uses the last positive saved volume instead of a saved zero without
erasing the zero-volume preference for unrestricted players.

`allow-muting="auto"` allows muting for unlimited playback and prevents it when `max-plays` is set;
explicit `true` and `false` values override that rule. Prevention covers both the muted state and
volume zero for the player's entire lifetime. System volume, browser-tab muting, and script
tampering remain outside the element's client-side enforcement.

The custom controls disable Pause, Seek, Mute, or Play whenever that action is unavailable. Hovering,
focusing, or pressing a locked control shows a short tooltip, and pressing it also writes the reason
below the player. Media events still enforce the same restrictions if playback is manipulated by
other browser features or scripts; these client-side controls are not tamper-resistant.

## Media selection and grading

Use element-managed directory selection when the chosen clip does not affect the answer. The
element sorts eligible files, chooses deterministically from the variant seed and player identity,
and saves the relative path in `data["params"]` during `prepare()`.

When the clip changes the prompt or correct answer, select it in the question's `generate()` first:

```python
import random


def generate(data):
    clip = random.choice(
        [
            {"file": "north.wav", "answer": "north"},
            {"file": "south.wav", "answer": "south"},
        ]
    )
    data["params"]["selected_clip"] = clip["file"]
    data["correct_answers"]["direction"] = clip["answer"]
```

```html
<pl-media-player
  file-name="{{params.selected_clip}}"
  max-plays="2"
  player-id="direction-prompt"
></pl-media-player>
<pl-string-input answers-name="direction"></pl-string-input>
```

The demonstration course includes both selection patterns, multiple players, a reload-safe player,
basic and limited videos, direct external audio, a YouTube embed, and a representative
language-listening question. Local-media demos keep their files in their own `clientFilesQuestion`
directories so they remain copyable through PrairieLearn content sharing.

## Development

Install Python 3.13+, uv, pnpm 11.19+, GNU Make, and Docker Desktop:

```sh
make deps
make check
make dev
```

Focused commands:

| Command                | Purpose                                                    |
| ---------------------- | ---------------------------------------------------------- |
| `make test-helpers`    | Run Python controller and repository tests.                |
| `make test-js`         | Run the playback-controller tests with Node's test runner. |
| `make validate`        | Validate PrairieLearn JSON and HTML/Mustache.              |
| `make vendor-verify`   | Verify checked-in PrairieLearn tooling dependencies.       |
| `make release-dry-run` | Preview the committed `main` → `release` build.            |
| `make release-build`   | Build/update the local release branch.                     |
| `make release-push`    | Build and push release with force-with-lease.              |

`release.toml` maps the committed element directory to the root of `release`, then adds this README
and the MIT license. `.github/workflows/release.yml` publishes that generated branch after a push to
`main`. The workflow never copies uncommitted working-tree content.
